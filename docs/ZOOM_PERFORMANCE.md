# 镜头缩放性能优化（2026-10-04）

缩放时原代码逐帧重绘物件和接触阴影，每个阴影的三层40点轮廓都重新执行相机投影、坐标逆变换与三角函数；物件和阴影还分别重复计算水域与深度排序。

本次优化：

- 正交相机的地面投影是仿射变换，窗口尺寸或镜头缩放变化时只计算一次，绘制时复用。仍保留贴图坐标的两次取整，阴影仍使用连续坐标。
- 缓存单位阴影轮廓，以投影基向量缩放生成原有三层轮廓，不减少顶点、透明度层数或阴影数量。
- 每次原有的重绘请求生成一份物件快照，物件层与阴影层共用，保留鸟类移动、植物生长和结算动画更新。
- 缓存固定河道的精确距离；不同判定半径共享距离，动态湖岸、水位和季节仍按原逻辑计算。缓存最多8192项，重建河道时清空。
- 只有窗口尺寸实际变化时才设置SubViewport尺寸。

未修改缩放端点、缓动曲线、拉远1.2秒/拉近0.8秒时长、24Hz常规物件更新、逐帧镜头重绘、画质、卡牌规则或存档格式。

## 验证

`python tests/prepare_visual_test.py zoom_performance`创建隔离测试工程。缩放专项比较3种窗口尺寸和3档缩放的原始Camera3D投影及40点阴影轮廓，并对400个坐标、4种半径检查缓存河道判定，实际运行拉近/拉远Tween核对端点，全部通过。

同一固定种子、同一80步缩放、643,200个阴影顶点的CPU计算对比：优化前2,703,981微秒，优化后361,418微秒，减少约86.6%。这是缩放绘制准备与阴影几何计算的微基准，未包含GPU提交、完整界面绘制或垂直同步，不代表实际帧率同比提升。

地图专项790项、完整界面930项以及补水/退水/浮岛/植物生长/结算回放测试通过。保持旧版玩法的独立工程也通过缩放和地图测试。该次导出的副本为`build/保卫鄱阳湖_镜头优化.exe`；性能优化现已包含在沙盘布局优化版及`build/保卫鄱阳湖.exe`中，并同步到9.30分支。


## 2026-10-07 镜头切换补充优化

菜单与局内切换时，高细分 PlaneMesh 每帧修改 size 会重建网格。现在预留远景端点的地面范围，只有更大的窗口或视野实际需要扩展时才增长，正常缩放不修改网格。固定景物以相机独立的连续深度排序，缩放与平移不再触发整批重排。40 点、三层阴影仍全部保留，但顶点变换改由原生 PackedVector2Array 批量完成。

切换从当前镜头位置起步，移除返回主菜单时先重置近景位置的突跳；仍保留远景 1.3、局内 GAME_CAMERA_ZOOM 端点和拉远 1.2 秒/拉近 0.8 秒时长。缓动改为 SINE / EASE_IN_OUT，起止速度平滑归零。镜头运动期间景物投影保持连续，不在每步投影中反复取整；结束后恢复静态像素对齐。减少动态效果直接切换到目标位置。

同机同一 80 步缩放、662400 个阴影顶点：本轮前 768325 μs，本轮后 95780 μs，CPU 准备开销减少约 87.5%（9.60 ms/步 → 1.20 ms/步）。此测量不包含完整 GPU 绘制，不代表整款游戏帧率增幅。

缩放测试检查所有原有投影和 40 点阴影轮廓，并新增 80 步期间地面网格尺寸不变、动画中断反向连续、返回菜单不跳回基准镜头的检查，全部通过。map_render 2420 项检查通过，18180 个水面阴影采样无覆盖错误。

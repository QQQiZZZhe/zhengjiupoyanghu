# 120 FPS 性能优化验证（2026-10-10）

游戏帧率上限保持 `run/max_fps=120`。动画时长、更新频率、季节演化、鸟群模拟、卡牌交互和完整结算预览保持原规则。

## 本轮处理

1. 停止上一轮连续对局的后台测试进程，排除额外测试负载。
2. 沙盘树木、建筑、植物、鸟类动作、船与浮岛使用共享纹理图集。原像素和逻辑纹理尺寸保持一致；绘制顺序和动作帧区域不变。图集在沙盘初始化时构建一次。
3. 地面接触阴影的原三层半透明多边形合并成一份三角网格，保留形状、透明度和叠加顺序。继续由原有变化键触发重建；每个绘制节点持有自己的网格资源，避免 RID 提前释放。
4. 每张卡牌的九层投影阴影合并为一次网格绘制，保留原投影、软边与层次。
5. 屏幕外的景物跳过绘制，保留 96 个沙盘局部像素的边缘裕量；对象模拟和深度排序继续运行，相机移动后正常重新出现。
6. 知识卡闪箔使用左上锚点匹配实际卡面几何更新，消除锚点与逐帧尺寸设置冲突的警告。

## 同机基线和复测

Godot 4.7.2，Compatibility/OpenGL，RTX 4060 Laptop GPU，独立测试存档。每个场景采样 240 帧；帧耗时采用两次真实 `process_frame` 的墙钟时间。脚本循环微基准与真实帧采样分开。旧 `Performance.TIME_PROCESS` 窗口会受微基准阻塞污染，因此不作为帧率证据。

| 场景 | 优化前绘制调用 P95 | 优化后绘制调用 P95 | 优化前帧耗时中位数 | 优化后中位数 | 优化后 P95 |
|---|---:|---:|---:|---:|---:|
| 手牌 | 1258 | 366 | 9.781 ms | 8.344 ms | 8.361 ms |
| 四张待执行牌 | 1278 | 386 | 10.329 ms | 8.335 ms | 8.362 ms |
| 查看沙盘 | 1017 | 174 | 8.686 ms | 8.325 ms | 8.366 ms |
| 五张待执行牌 | 未采基线 | 397 | 未采基线 | 8.336 ms | 8.361 ms |
| 五张牌、1600×900 | 未采基线 | 360 | 未采基线 | 8.328 ms | 8.361 ms |

四张待执行牌的绘制调用减少约 70%。本机上述采样场景已接近 120 FPS 的 8.33 ms 帧预算；这是固定测试场景的测量，不代表所有硬件、后台负载与瞬时资源加载都能保证同一帧率。

- `knowledge_cards`：244 项检查通过，无此前闪箔尺寸警告。
- `runtime_performance`：796 项检查通过，静止轮廓不重绘、静止弹簧无重复唤醒、缓存预测正确且不消耗游戏随机流。
- `animation_performance`：通过，船轨迹、地形投影、景物深度顺序保持一致。
- `preview_performance`：五种场景完成采样，确认 `Engine.max_fps == 120`。
